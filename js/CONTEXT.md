## v20.5 — no auto-pause, THE AUTOBRUSH (13 Nov 2026)

Two behavior changes, both additive. **The run is never paused out from under the hand any more**: the `blur`/`visibilitychange` pause hooks are gone from `main.js` — REST stays a choice (Escape, the button). A hidden tab still stills its own frames (the browser throttles rAF), but returning finds the sheet live, not the REST door. **THE AUTOBRUSH (自)** — the second scroll's gift: a settings-room toggle (`om_autobrush_v1`, device-local like REALLY HARD, WIPE sweeps it) whose row stays hidden until `getUnlocked() >= 2`. A run begun in its keep is steered by `autoSteer` (repelled by the near horde and spite-drops, drawn to the nearest mote, drifting off bounded margins) — fed in through `main.js`'s per-frame `vec()` poll via `G.autoVec(0, 0)`, which yields to any real key or finger. Its score pays half (`killEnemy`, floored to the 5-grid), the HUD wears the inked 自 beside the 難, and the toggle is read once per run so mid-run changes never re-price spilled ink. The purse/ink economy is deliberately untouched — only score is halved.

## v20.3 render performance pass (11 Nov 2026)

Three render-side savings, all additive to the existing cache discipline: the entities that can crowd the sheet (bullets, enemy bullets, enemies, idle wanderers, motes, pickups, particles) now cull against the same world-space view rect the stains already used — off-paper bodies no longer build blob paths at all (at the horde cap most beasts are usually beyond the eye); the eye's vignette is baked once into a quarter-res offscreen sheet keyed by the existing `vgKey` and blitted per frame instead of a full-screen gradient fill (the low-HP red rim keeps its cached gradient + alpha pulse); and the twelve wash pairs call `decode()` at load so the first `drawImage` of a wash no longer stalls the frame it lands in. Wash-chunk baking (compositing master washes into world-space chunk canvases) remains the next documented step. Cache `v20.3`.

## v20.1 correctness pass (11 Nov 2026)

Six audit fixes, all verified against source: the hit-grid pool now clears reused cell arrays (`arr.length = 0` in `buildHitGrid`) — stale enemies no longer accumulate across frames, so pierce/blade/boomerang no longer multi-hit one body and long runs keep their collision speed; daily runs pin their sheet at `startRun` (`S.dailyDay`) so a run crossing midnight files under the day it began (ghost included, via `ghostSave`'s day override); corrupt-typed saves can no longer NaN-cascade into `charmCap`/`frontierLevel` (`num`/`obj` validators on every numeric read); the bomb pickup's damage now matches its visible ring radius instead of striking the whole sheet; the global keydown handler no longer steals Space from focused buttons; and `drawEnemy` composes its ink strength through `EN_ALPHA` (caller alpha × tracer factor) instead of ~28 branches snapping to full opacity — faint wanderers and tracer echoes now stay faint end to end. ## Cross-device private save bridge (4 Nov 2026)
`cloud-save.js` stores whitelisted `om_*` progression keys in private, Google-user-owned Supabase `om_player_saves` using the single `lb.js` SDK/client. It does **not** replace local gameplay saves. Revisioned snapshots, backup-before-restore and compare-and-swap protect independent PC/phone progress. A played device explicitly backs up on first migration; a blank new device restores, then subsequent saves auto-sync unless both diverge. `lb.js` exposes only the authenticated client through `cloudAccess()` and notifies the bridge on auth changes; `main.js` marks local WIPE so it never silently overwrites cloud. `index.html` loads the bridge after `lb.js`; `sw.js` precaches it. v19.3 uses the purse/charms economy; the allowlisted `om_stone_v1` is retained only as legacy-save compatibility. Test with `node .github/cloud-save.test.cjs`. Never auto-merge currency or conflicting snapshots, and never allow one player's save to be fetched by another.

## Key files
`main.js` bootstraps the game; `game.js` owns runs; `render.js`, `ui.js` and `intro.js` handle presentation; `lb.js` reads/writes `om_scores` and `om_daily`; `supabase-config.js` holds only the public Pinpoint-project Supabase URL and publishable key. `firebase-config.js` is an unused placeholder unless separately integrated.

## Connections
`index.html` loads `supabase-config.js` before `lb.js`, and `sw.js` precaches both files. The Supabase SDK loads lazily on leaderboard use. Scores belong only in ONE MORE's `om_*` tables, never Pinpoint's tables.

## Google OAuth return (2 Nov 2026)
`lb.js` writes the short-lived `om_lb_google_return_v1` sessionStorage intent (tab and timestamp only) immediately before navigating to Google. On a new document `main.js` synchronously calls `LB.consumeOAuthReturn()`; a recent marker or a PKCE `?code`/OAuth error return bypasses the intro, boots the title canvas and reopens the correct leaderboard tab. The SDK's lazy `init()` then consumes the PKCE callback. No credentials are stored in the intent. Normal launches still play the intro. OAuth errors now display a targeted token-exchange message instead of a generic sign-in failure; failed OAuth query and hash parameters are removed from the browser URL after capture, preserving successful `?code` for PKCE. Browser integration still requires checking on GitHub Pages. **2026-11-02 server log:** `oauth2: invalid_client` / `The provided client secret is invalid` (Google provider is enabled, but its client secret must be corrected in the shared Pinpoint Supabase project by the project owner). Logs also show anonymous sign-ins disabled; re-enable Auth Anonymous provider for anonymous sign-in. No database/table fix is needed.

Before overwriting this folder via manual upload, compare with the preserved snapshot tags and [root recovery runbook](../SUPABASE-RECOVERY.md). Never copy older `main.js` wholesale over v19+ themes/game UI. The single-branch repair workflow proposes only an Actions patch artifact for review. The read-only Actions guard checks essential markers but cannot test live Google OAuth. Retain the new game's gameplay changes and selectively merge this folder's Auth/leaderboard logic.
