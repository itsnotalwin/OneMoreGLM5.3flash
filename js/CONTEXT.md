## v21.2 — the autobrush walks a danger field (13 Nov 2026)

The walker's third brain, replacing the hand-tuned radius clusters: a **danger-field navigator**. Every body of spite pushes by inverse square (`w × 26000 / d²` with a soft core, guardians ×4.2, captains ×2.4, talls ×1.8) — the field itself shows the gap in a horde and sets the equilibrium distance to a lone wolf (~165px), so one constant replaces every magic radius. ## Cross-device private save bridge (4 Nov 2026)
`cloud-save.js` stores whitelisted `om_*` progression keys in private, Google-user-owned Supabase `om_player_saves` using the single `lb.js` SDK/client. It does **not** replace local gameplay saves. Revisioned snapshots, backup-before-restore and compare-and-swap protect independent PC/phone progress. A played device explicitly backs up on first migration; a blank new device restores, then subsequent saves auto-sync unless both diverge. `lb.js` exposes only the authenticated client through `cloudAccess()` and notifies the bridge on auth changes; `main.js` marks local WIPE so it never silently overwrites cloud. `index.html` loads the bridge after `lb.js`; `sw.js` precaches it. v19.3 uses the purse/charms economy; the allowlisted `om_stone_v1` is retained only as legacy-save compatibility. Test with `node .github/cloud-save.test.cjs`. Never auto-merge currency or conflicting snapshots, and never allow one player's save to be fetched by another.

## Google OAuth return (2 Nov 2026)
`lb.js` writes the short-lived `om_lb_google_return_v1` sessionStorage intent (tab and timestamp only) immediately before navigating to Google. On a new document `main.js` synchronously calls `LB.consumeOAuthReturn()`; a recent marker or a PKCE `?code`/OAuth error return bypasses the intro, boots the title canvas and reopens the correct leaderboard tab. The SDK's lazy `init()` then consumes the PKCE callback. No credentials are stored in the intent. Normal launches still play the intro.
